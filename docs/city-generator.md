# Procedural city generator

`src/core/three/city/` builds whole cities from a seed: a road network that is not a plain grid,
districts, lots and buildings, props, traffic and pedestrian data, and a streamed three.js view
with day, golden-hour and neon-night looks. It is opt-in: nothing in `@core` imports it and no
existing game uses it, so shipped games do not change.

- **Import.** `@core/three` re-exports it for 3D games. A plain three.js page (the preview tool)
  imports `src/core/three/city` directly. Headless code (Node tests, bots, workers) imports
  `src/core/three/city/data`, which has no three.js.
- **Art.** Everything is generated by code: geometry, colours, windows and markings drawn by the
  shaders. No textures are loaded. An optional hook can put CC0 models on landmark lots
  ("hybrid", below).

## Preview tool

`npm run dev`, then open `/tools/city-preview/` (dev only: it is not a game, not in the platform
catalogue and not part of `npm run build`).

- **Panel.** Seed (🎲 for a random one), style, size, look, district mix sliders, detail radius,
  and toggles for props, far LOD, wireframe, lane graph, colliders, pedestrian graph, minimap and
  shadows. The URL keeps the city: `?seed=7&style=coast&size=1400&look=night`.
- **Cameras.**
  - Overview: orbit, drag to turn, right drag or two fingers to pan, wheel or pinch to zoom.
  - Fly: WASD, Q/E down and up, Shift fast, drag to look.
  - Street: walk at eye height, WASD, Shift to run, drag to look; buildings, walls, poles and
    trunks block you (the plan's colliders). On touch the left half of the screen is a stick and
    the right half looks around.
- **Stats line.** Plan time, chunks (loaded, queued, cached), chunk build time, draw calls,
  triangles, GPU geometries and textures, ms per frame.
- **Screenshot set** downloads an aerial and three street views by day and by night.
- `window.__city` holds the hooks the scripts use (`generate`, `aerial`, `street`, `settle`,
  `measure`, `capture`, `minimap`, `laneCrop` …).

## API

```ts
import { generateCity, cityQuery, CityView, signalState } from '@core/three';

const plan = generateCity({ seed: 42, style: 'metropolis', size: 1800, districts: { park: 1.5 } });
const q = cityQuery(plan);
q.roadAt(x, z);              // { edge, node, s, lateral } on asphalt, else null
q.nearestLane(x, z, yaw);    // { lane, s, d, x, z, dx, dz }: lanes facing the yaw count as nearer
q.lotAt(x, z); q.blockAt(x, z); q.surfaceAt(x, z); // 'road' | 'sidewalk' | 'building' | 'water' | 'park' …
q.collides(x, z, radius); q.heightAt(x, z); q.drivable(x, z); q.walkable(x, z);

const view = new CityView(plan, world.scene, { look: 'night', near: 320 });
world.onFrame = (dt) => view.update(player.position, world.camera, dt);
```

`generateCity(options)`:

| option | |
|---|---|
| `seed` | any integer; the same options always give the same plan (`planHash(plan)`) |
| `style` | `metropolis` (Neon Metropolis / Neon Metropol), `coast` (Sunny Coast Town / Güneşli Sahil Kasabası), `industrial` (Old Industrial / Eski Sanayi Şehri), `suburbia` (Suburbia / Banliyö), `harbor` (Harbor City / Liman Şehri) |
| `size` | side of the square in metres (styles default to 1400–2000) |
| `districts` | multipliers of the style's district weights: `downtown`, `commercial`, `residential`, `suburban`, `industrial`, `docks`, `park` |
| `water` | override: `river`, `coast`, `both`, `none` |
| `ring` | ring road on or off |
| `height` | building height multiplier |

### The plan (`CityPlan`, plain data)

Units are metres; x runs east, z south, y up; a heading `h` faces `(sin h, cos h)` (three.js
`rotation.y`). Traffic keeps right.

- **Roads.**
  - `nodes`: junctions, bends and dead ends, each with its asphalt outline, traffic lights
    (`signal`, `phase`), crosswalks and a roundabout island radius.
  - `edges`: streets as centreline polylines with class (`boulevard` with a planted median,
    `avenue`, `street` with parking strips, `alley`), lanes per direction, half width, bridge
    flag, the trims where the junctions take over, the blocks on each side and a name.
- **Blocks.** Kerb outline, sidewalk width, inner outline, district, ground; kinds `block`,
  `park`, `plaza`, `water` (a river between its quays) and `outer` (the city's edge).
- **Lots.** Oriented boxes along the street fronts (front on the sidewalk), with the road they
  face and their use: building, parking, container yard, gas station.
- **Buildings.** Type (tower, office, midrise, shop, apartment, rowhouse, house, warehouse,
  factory, gas), footprint, height, floors and floor height. Parts are boxes with a kind:
  masses with a roof (flat, gable, hip, sawtooth) and a facade style (punched, glass, ribbon,
  brick, shed, house), and roof boxes, water tanks, antennas, spires, lit crowns, helipads,
  awnings, shop signs, balconies, fire escapes, chimneys, gas station canopies, roof stair
  houses, loading doors and garages. Also the front door, a roof reachable by stairs
  (`roofAccess`), a landmark tag and the lit-window share at night.
- **Props.** Lamps, traffic lights, trees (leafy, palm, conifer), benches, bins, hydrants, bus
  stops, parked cars, containers, dock cranes, pumps, fountains, statues, planters, ponds, pools
  and beach umbrellas. `walls` holds fences, hedges and chain-link.
- **Traffic.**
  - `lanes`: polylines with direction, index, speed and the connectors leaving their end.
  - `connectors`: curves through each junction with their turn (straight, left, right, U-turn)
    and signal group. U-turns happen at dead ends only, and roundabouts circulate anticlockwise.
  - `signals`: the pole positions. `signalState(node, group, t)` gives green, yellow or red on a
    30 s cycle.
- **Pedestrians.** `walk`: a ring along every block's sidewalk, with crossings at the junctions.
- **Spawns.** Start, free parking spots, doors, rooftops, gas stations, the tallest tower,
  parks, plazas, bridges and dock cranes.
- **Collision.** `colliders`: oriented boxes with a height range (building masses, walls,
  fences). `circles`: poles, trunks, fountains.
- **Water.** River and sea outlines and beaches. The minimap comes from `minimapRaster(plan,
  res)` (one byte per cell), `minimapVector(plan)` or `drawMinimap(ctx2d, plan, scale, { lanes,
  colliders, spawns, walk })`.

### How a city is laid out

1. **Site.**
   - The perimeter road, inset from the square, or the coast promenade on the sea side with a
     beach in front of it.
   - A meandering river between two quay roads.
   - A downtown centre kept away from the water.
   - A district field: downtown in the middle, then a commercial ring, residential, suburbs on
     the edge. Industry sits in a noise-chosen sector and docks along the water. The borders are
     noisy, so districts blend.
2. **Skeleton.** The roads go into one planar graph (every crossing split, nearby nodes snapped)
   in priority order:
   - perimeter, quays and the ring road (an ellipse round downtown);
   - diagonals from the centre;
   - the borders of 2–3 Voronoi grid zones, which become avenues;
   - each zone's own street grid: its own angle, spacing by district, every 4th line an avenue,
     wavy in the curvy styles.

   Pieces that would run alongside an existing road are left out.
3. **Water and cleanup.**
   - A few crossings become bridges: the perimeter and ring always, others spaced apart. The
     rest of the wet edges go.
   - Short edges merge, stubs and sharp angles (under ~32°) go, and junctions keep at most five
     roads.
   - Some local streets are dropped for bigger blocks and T junctions.
   - Alleys cut big downtown blocks, and cul-de-sacs reach into big suburban ones.
4. **Junctions and blocks.**
   - Chains are collapsed into street polylines. Every junction gets kerb corners: line
     crossings with rounded fillets, arcs round dead ends and cul-de-sac bulbs, roundabouts
     (1–2 per city).
   - Roads are trimmed where the junction outlines start, so asphalt never overlaps.
   - A block's kerb outline is walked from those corners. Faces whose kerbs cross mean
     overlapping roads: the weaker road goes and the step repeats.
5. **Lots and buildings.**
   - The sidewalk is inset from the kerb (narrow necks are cut).
   - Lots are cut along each street front, longest fronts first, shrinking until they fit
     without overlapping.
   - Buildings come from the district: height falls off with the distance to the centre, so the
     skyline peaks downtown.
   - The tallest tower gets a spire.

## Drawing and streaming (`CityView`)

- **Chunks.** 128 m squares. Within `near` (default 320 m) of the focus a chunk is built in full:
  - one merged mesh with one material: roads with markings, junctions, kerbs, sidewalks,
    grounds, buildings, fences and small props;
  - instance records for trees, lamps, traffic lights, parked cars and containers, drawn by one
    `InstancedMesh` per kind for the whole view and refilled when the chunk set changes;
  - lamp halos (one more instanced mesh).

  Up to `budget` ms of chunk building runs per update, nearest first. A chunk that leaves frees
  its GPU geometry at once and keeps its arrays in a CPU cache (96 chunks) for a fast return.
- **Far LOD.** Every building as an inset box with the same window shader, in 512 m tiles, over a
  ground map (the plan rasterised at about 3 m per texel). A far box hides itself (vertex shader)
  once its building's chunk is loaded. Past the map, a coarse ground grid carries on, and a water
  plane shows wherever the ground map has water.
- **Materials.**
  - The city material is a Lambert with vertex colours. Its shader switches on a per-vertex kind
    and draws windows (by floor and bay from UVs in metres, lit by a hash per window at night,
    shopfronts on the ground floor), lane markings, stop lines, crosswalks, parking bays, paving
    joints, brick courses, corrugated metal, roof tiles and traffic light phases.
  - The others are water (ripples, sky reflection, sun glints, city lights), a sky dome
    (gradient, sun, stars, city glow) and additive lamp halos.
- **Night.** A light map baked once on the CPU (lamp pools, shop glow, gas station canopies)
  lights the ground and lower walls. There are no per-lamp lights.
- **Looks.** `day` (Sunny day / Güneşli gün), `golden` (Golden hour / Altın saat), `night` (Neon
  night / Neon gece) and `overcast` (Kapalı hava). Each sets sky, sun, ambient, fog, water and
  the night amount. `view.setLook(id)` switches live.
- **Shadows.** One sun casts them, its shadow box following the focus (`shadowExtent`, 110 m).
  Only the chunks inside that box and the trees throw shadows. Night has no sun shadows.
- **Prop distances.** Instanced props are drawn nearer than the chunks: trees and lamps within
  230–260 m, traffic lights within 200 m, containers within 220 m and parked cars within 170 m.
  They are refilled as the focus moves.
- **Hybrid.** Pass `replace: (building) => Object3D | null` to put a loaded model (for example a
  CC0 GLB through `loadModel` / `model()`) on a landmark or tower lot. The view fits it to the
  footprint, and the procedural building and its far box are left out.
- **Other calls.** `view.setNear()`, `setLod()`, `setProps()`, `setShadows()`, `setWireframe()`,
  `overlay('lanes' | 'colliders' | 'walk', on)`, `loadAll(focus)` (no pop-in on the first frame)
  and `stats()`. `dispose()` frees everything, and a `World3D` frees what is left in its scene
  on shutdown anyway.

### A game using it

1. In `createGame()`:
   - `plan = generateCity({ seed, style })`;
   - `view = new CityView(plan, world.scene, { look })`, without `world.addLights()`, since the
     view brings its sun and sky light;
   - `view.loadAll(start)`.
2. Each frame: `view.update(player.position, world.camera, dt)`.
3. Gameplay queries: drive on `q.roadAt()`, follow `plan.lanes` and `connectors` for traffic,
   respect `signalState()`, walk the `walk` graph, collide with `q.collides()`, spawn at
   `plan.spawns`, draw the HUD minimap with `drawMinimap()`.

## Budget (measured)

These were measured in the repo's headless Chromium (SwiftShader, so frame times mean nothing)
and in Node on a shared 4-core machine. Draw calls and triangles are counted at the GL level, with
the shadow pass included. `renderer.info` leaves the shadow pass out and shows about a third less.

| | |
|---|---|
| plan generation, Node (`scripts/city-unit.ts`, warm) | 230–600 ms, mean about 350 ms over 5 styles × 3 seeds (1.4–2 km); 2 km metropolis 500–600 ms |
| plan generation in the browser, first city of the page | 0.5–1.3 s (cold JIT, busy machine) |
| `new CityView` (ground and light maps, far LOD, instanced meshes) | 150–700 ms |
| chunk build (128 m, CPU) | 2–5 ms on average; a street view loads about 30–40 chunks |
| street view (320 m detail radius, day with shadows) | 30–43 draw calls, 136–314k triangles |
| street view at night (no sun shadows) | 30–34 draw calls, 136–207k triangles |
| low aerial (450 m radius) / full aerial (650 m) | about 90 / 128 draw calls, 0.6–1.2M triangles: an overview, not a game camera |
| GPU memory (`scripts/city-memory.mjs`) | geometries 46 → 46 → 46 and textures 3 → 3 → 3 over three trips across a 2 km city and back (after a warm-up trip); 42 → 42 → 42 over three regenerations |
| GPU textures per view | 3: ground map and light map (1024² RGBA each) and the shadow map |

## What is still simple

- The whole city is flat: no terrain, no hills.
- Cars and people are not simulated: the plan carries lanes, signals and walkways for a game to
  use.
- Buildings are boxes with shader windows; there are no interiors.
- Rivers end where the ground map ends (about 0.3 × the size past the city), with a jagged
  edge seen up close.
- Acute junctions (diagonals across the grid) can make wide asphalt areas.
- A few leftover islands between tangled roads become small plazas without walkways.
- Aerial views with a big detail radius are heavy: use the far LOD for overviews in a game.
